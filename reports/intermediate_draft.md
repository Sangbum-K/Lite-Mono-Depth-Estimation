<!-- abstract -->
본 프로젝트는 RGB 영상 한 장에서 픽셀별 깊이를 추정하는 단안 깊이 추정 문제를 다룬다. Baseline인 Lite-Mono(CVPR 2023)를 원 논문과 같은 KITTI Eigen-Zhou split으로 학습했고, Eigen test에서 AbsRel 0.107을 얻어 논문의 결과를 재현했다. 재현한 모델의 오차를 분석한 결과, 오차는 물체와 배경이 만나는 깊이 경계에 집중되었고 물체의 깊이가 배경 쪽으로 번지는 현상이 가장 크게 나타났다. 자율주행에서 중요한 가까운 물체의 경계를 기준으로, 번짐의 원인을 decoder 구조와 자기지도 학습 손실의 두 가설로 나누고 추론 시간을 거의 늘리지 않는 수정 후보로 비교했다. 5 epoch 예비 실험에서 decoder를 바꾼 후보(Depth Pro 2의 decoder 구조를 가져온 후보 포함)와 smoothness를 바꾼 후보는 번짐을 줄이지 못했다. 학습 손실을 경계 주변에서 직접 측정한 결과, photometric loss는 경계 바로 옆 배경에서 물체 깊이와 배경 깊이를 구분하지 못했고, 경계에서 약 8픽셀 이내에서는 물체 깊이 쪽으로 치우쳤다. 손실이 이렇게 치우친 경계에서는 모델이 번진 비율이 35%로 나머지 경계(24%)보다 11%p 높았다. 이에 경계에 별도의 학습 신호를 주는 방법을 다음 단계로 제안한다.

# 1. 서론

단안 깊이 추정(monocular depth estimation)은 카메라 한 대로 촬영한 RGB 영상 한 장에서 픽셀별 깊이를 추정하는 문제다. 영상 한 장에는 거리 정보가 직접 담겨 있지 않으므로, 모델은 물체의 크기, 원근, 가림(occlusion) 같은 단서로 깊이를 추론해야 한다. 자율주행에서는 LiDAR가 정확한 거리 정보를 제공하지만 비용이 높아, 카메라 영상만으로 거리를 인식하는 방식이 함께 사용되고 있다. Ground truth 깊이를 수집하는 데에도 LiDAR가 필요하므로, 연속된 영상 프레임만으로 학습하는 자기지도(self-supervised) 방식이 널리 연구되고 있다.

Baseline으로는 경량 자기지도 모델인 Lite-Mono를 선택했다. Lite-Mono는 Monodepth2보다 파라미터 수가 약 78% 적으면서 AbsRel도 낮아, 차량처럼 연산 자원이 제한된 환경에 적합하다. 또 학습 방식은 Monodepth2를 유지하고 모델 구조만 바꾸었기 때문에, 개선안을 적용했을 때 그 효과를 다른 요인과 구분하기 쉽다. Proposal 이후 baseline을 직접 학습해 논문의 결과를 재현했고, 재현한 모델의 실패 사례를 분석해 개선할 한계를 정했다. 본 보고서는 재현 과정과 결과, 한계 분석, 이를 바탕으로 한 개선 아이디어와 예비 실험 결과를 다룬다.

# 2. 데이터셋

## 2.1 KITTI raw

KITTI는 차량 주행 중 수집한 데이터셋으로, 스테레오 컬러 영상과 Velodyne LiDAR 측정값, GPS/IMU 정보, 카메라 보정 정보를 포함한다. 본 프로젝트에서는 Lite-Mono 원 논문과 같이 KITTI raw를 사용한다. 라이선스는 CC BY-NC-SA 3.0으로 비상업적 연구 목적으로 사용할 수 있으며, 전체 용량은 약 175GB다.

## 2.2 데이터 분할

원 논문과 같이 학습·검증에는 Eigen-Zhou split을, 최종 평가에는 Eigen test 697장을 사용한다. Eigen-Zhou split은 Eigen split의 학습 장면에서 카메라가 거의 움직이지 않은 프레임을 제외한 뒤, 남은 프레임을 학습용과 검증용으로 나눈 것이다. 학습 샘플은 같은 카메라로 촬영한 연속된 세 프레임(t−1, t, t+1)으로 구성하고, LiDAR 깊이값은 학습에는 사용하지 않고 평가에만 사용한다.

Split 목록은 Monodepth2의 공식 파일을 그대로 사용했다. Lite-Mono 논문에는 학습 이미지 수가 39,180장으로 적혀 있지만 공식 목록은 39,810장이므로, 논문의 표기 오류로 보고 공식 목록을 따랐다. 별도의 데이터 샘플링 없이 전체 분할을 사용했다.

<!-- table widths=1650,900,2056 caption="사용한 KITTI split" -->
| Split | 이미지 수 | 용도 |
|---|---|---|
| Train (Eigen-Zhou) | 39,810 | 학습 (t−1, t, t+1) |
| Val (Eigen-Zhou) | 4,424 | 학습 중 검증 |
| Test (Eigen) | 697 | 최종 평가 (LiDAR GT) |

## 2.3 전처리 및 평가 방법

입력 영상은 640×192로 크기를 조정하고, 학습 시에는 50% 확률로 좌우 반전을 적용하며 color jitter는 세 프레임에 동일하게 적용한다. Proposal에서는 Monodepth2와 같은 방식으로 원본 PNG 영상을 JPG로 변환할 계획이었으나, 실제 학습에서는 변환하지 않고 원본 PNG를 그대로 사용했다. JPG로 학습된 공개 checkpoint를 PNG 영상으로 평가했을 때도 논문과 같은 수치가 나왔으므로, 평가에서는 영상 포맷에 따른 차이가 거의 없다. 학습에서 포맷에 따른 차이는 아직 비교하지 않았다.

평가는 원 논문과 같은 방식으로 Eigen test 697장에 대해 진행하며, LiDAR 측정값을 ground truth로 사용한다. 자기지도 방식으로 학습한 모델은 깊이의 절대적인 scale을 알 수 없으므로, 이미지마다 median scaling을 적용해 예측 깊이의 scale을 ground truth에 맞춘다. 또 80m 이내의 깊이만 사용하고, 원 논문과 같은 영상 중앙 영역(Garg crop)만 평가한다.

# 3. Baseline: Lite-Mono

자기지도 단안 깊이 추정 모델은 depth network와 pose network로 구성된다. Depth network는 입력 영상의 disparity 맵을 추정하고, pose network는 인접한 두 프레임 사이의 카메라 움직임을 추정한다. 두 추정값으로 인접 프레임에서 현재 영상을 재구성하고, 실제 영상과의 차이(photometric loss)를 줄이도록 학습하므로 ground truth 깊이가 필요 없다. 추론에는 depth network만 사용한다.

**구조.** Lite-Mono의 depth network는 encoder-decoder 구조다. Encoder는 네 단계로, 첫 단계에서 convolution으로 해상도를 절반으로 줄이고, 나머지 세 단계마다 여러 CDC 모듈과 하나의 LGFI 모듈을 순차적으로 배치해 1/4, 1/8, 1/16 해상도의 feature를 만든다. CDC는 dilation rate가 서로 다른 depth-wise convolution으로 파라미터를 늘리지 않고 receptive field를 넓히고, LGFI는 채널 간 attention으로 적은 연산량으로 global context를 반영한다. Decoder는 encoder 세 단계의 feature를 bilinear upsampling으로 키운 뒤 결합하여 disparity를 출력한다. Pose network와 학습 손실은 Monodepth2와 같다.

**선행연구 개선점.** Monodepth2(14.3M)는 convolution만 사용해 receptive field가 제한되고, Transformer 기반 모델은 정확도는 높지만 모델이 크고 느렸다. Lite-Mono는 CDC와 LGFI로 두 문제를 함께 완화해 3.1M으로 AbsRel 0.107을 기록했다.

**한계.** Proposal에서는 학습 방식이 Monodepth2와 같아 움직이는 물체에서 오차가 생길 수 있다는 점을 한계로 예상했다. 이번 분석에서는 이와 별개로, 깊이 경계에서 물체의 깊이가 배경 쪽으로 번져 오차가 크게 나타나는 한계를 찾았다(5장).

# 4. Baseline 재현

## 4.1 학습 설정

학습은 Lite-Mono 공식 저장소의 코드와 README에 제시된 학습 명령을 따랐다. 공식 코드의 기본값은 batch 16, 50 epoch로 논문의 설정과 달라, 논문과 같은 batch 12, 30 epoch를 직접 지정했다. 전체 설정은 아래 표와 같다.

<!-- table widths=1500,3106 caption="학습 설정" -->
| 항목 | 설정 |
|---|---|
| 코드 | 공식 저장소 (commit 4874b35) |
| 입력 해상도 | 640 × 192 |
| 입력 영상 | 원본 PNG (논문: JPG) |
| Encoder 초기화 | ImageNet 사전학습 가중치 |
| Batch / Epoch | 12 / 30 |
| Optimizer | AdamW (weight decay 0.01) |
| Learning rate | Depth 1e-4→5e-6, Pose 1e-4→1e-5 (cosine) |
| Loss | Photometric(SSIM+L1), min. reprojection, auto-masking, smoothness |
| Seed | 고정하지 않음 (공식 코드와 같음) |

공식 코드는 이전 버전의 라이브러리를 기준으로 작성되어 최신 환경에서는 그대로 실행되지 않았다. 이에 따라 Pillow, torchvision, NumPy에서 삭제된 함수를 대체 함수로 바꾸었고, 학습과 평가의 계산 과정은 수정하지 않았다. 또 평가 코드에는 PNG 옵션을 주어도 항상 JPG 파일을 읽는 오류가 있어, PNG 파일을 읽도록 수정했다. 데이터를 불러오는 worker 수는 기본값 12에서 RAM이 부족해 학습이 중단되었으므로 6으로 줄였다.

## 4.2 실험 환경

실험은 로컬 서버(NVIDIA RTX 5070 12GB, Ubuntu 24.04, PyTorch 2.11/CUDA 12.8, RAM 15GB)에서 진행했다. 원 논문도 12GB GPU 한 장으로 학습했으므로, 데이터를 줄이지 않고 논문과 같은 batch 크기로 학습할 수 있었다. 학습 중 GPU 메모리는 약 8.4GB를 사용했고, 30 epoch 학습에 약 9시간(epoch당 약 18분)이 걸렸다. GPU 사용률은 약 47%에 머물렀는데, worker 수를 줄여 데이터를 불러오는 속도가 학습 속도를 따라가지 못했기 때문일 가능성이 높다. 모델의 파라미터 수는 3.07M, FLOPs는 5.03G다.

## 4.3 정량 결과

원 논문과 같이 마지막 epoch의 checkpoint로 평가했다. AbsRel, RMSE log, δ1~δ3는 논문과 0.001 이내로 일치해 baseline을 재현했다. 반면 SqRel은 0.821로 논문(0.765)보다 약 7% 높고, RMSE도 4.608로 논문(4.561)보다 조금 높다. SqRel은 오차를 제곱해 평균하므로 큰 오차에 민감한 지표로, 학습 후반의 epoch 사이에서도 0.795~0.867 범위로 변동했다. 이 때문에 이 차이가 PNG 입력에 의한 것인지, seed를 고정하지 않아 생긴 학습 간 편차인지는 아직 구분할 수 없다.

같은 평가 코드로 공개 checkpoint를 평가하면 논문 수치가 그대로 나오므로, 평가 과정의 문제는 아니다. 본 프로젝트는 이 재현 모델을 이후 실험의 baseline으로 사용한다.

## 4.4 정성 결과

그림 1은 test 영상 중 무작위로 고른 세 장의 예측 결과다. 도로, 주차된 차량, 나무처럼 장면의 전체적인 깊이 구조는 대체로 맞게 예측한다. 오차는 도로 면처럼 평평한 영역에서는 작지만, 차량과 나무의 윤곽, 먼 건물과 수풀 근처에서 크게 나타난다. 다음 장에서는 이 오차가 어디에 얼마나 집중되는지 분석한다.

# 5. 한계 분석

## 5.1 오차 분포

먼저 오차가 일부 이미지에 몰려 있는지 보기 위해 Eigen test 697장의 이미지별 AbsRel을 계산했다. 오차가 가장 큰 10%의 이미지가 전체 오차에서 차지하는 비율은 약 18%로, 특정 이미지에서만 크게 틀리기보다는 대부분의 이미지에 비슷한 오차가 있다.

다음으로 LiDAR 점 단위로 오차를 나누어 보았다. 깊이 경계는 LiDAR 점 주변 9×9 영역 안에서 깊이가 1.25배 이상 차이 나는 점으로 정의했다. 깊이 경계 근처의 점은 전체의 11.5%이지만 전체 오차의 28.1%를 차지하며, AbsRel은 0.260으로 평평한 영역(0.086)의 약 3배다. 거리별로는 40m 이상에서 AbsRel이 0.201로 가장 높지만, 해당 점은 전체의 5.7%로 적어 전체 오차에서 차지하는 비율은 10.8%다.

## 5.2 깊이 경계 번짐

그림 2는 예측 깊이에서 찾은 경계를 입력 영상 위에 표시한 것이다. 차량 지붕(1, 2), 나무 기둥(3), 보행자(5) 모두 예측 경계가 실제 윤곽보다 바깥쪽에 위치해, 물체가 실제보다 크게 예측된다. 그림 3은 보행자의 경계를 확대한 것이다. LiDAR 깊이에서는 보행자와 뒤쪽 도로의 경계에서 깊이가 바로 바뀌지만, 예측에서는 보행자의 깊이가 몇 픽셀에 걸쳐 배경으로 퍼져 경계가 흐려진다.

번짐의 정도를 수치로 나타내기 위해, 양쪽 깊이가 일정한 LiDAR 깊이 경계 3,263개에서 예측 경계와 실제 경계 사이의 거리를 측정했다. 예측 경계가 실제 경계에서 4px 이내에 있는 경우는 25.4%에 불과했고, 배경 쪽으로 4px 이상 밀린 경우가 27.7%로 물체 쪽으로 밀린 경우(7.1%)의 약 4배였다.

## 5.3 원인 분석

번짐의 원인을 찾기 위해 Lite-Mono의 decoder 구조를 살펴보았다. Encoder의 첫 단계는 1/2 해상도의 feature를 만들지만, 이 feature는 다음 단계의 입력으로만 사용되고 decoder에는 전달되지 않는다. 이에 따라 decoder가 사용하는 가장 세밀한 feature는 1/4 해상도다. 또 decoder는 1/2 해상도에서 disparity를 출력한 뒤, bilinear upsampling으로 크기만 2배로 늘려 최종 결과를 만든다.

이 구조는 두 가지 이유로 경계를 흐리게 만들 수 있다. (1) 해상도: 1/4 해상도의 픽셀 하나는 원본 영상에서 약 8픽셀에 해당하므로, 이 정도의 정보로는 경계의 정확한 위치를 정하기 어렵다. (2) 보간: bilinear upsampling은 주변 픽셀 값의 가중 평균으로 새 픽셀을 채우므로, 깊이가 갑자기 바뀌는 경계에서 물체와 배경 사이의 중간 깊이가 만들어진다. 이 구조는 경계가 수 픽셀씩 밀리는 원인 후보 중 하나이며, 학습 손실 쪽의 원인은 6.2절에서 함께 다룬다. 두 후보의 검증 결과는 6.5–6.7절에 정리했다.

한편 LiDAR와 카메라는 차량에 설치된 위치가 달라, 경계 근처에서는 카메라에는 가려서 보이지 않는 뒤쪽 면이 LiDAR에는 측정되는 경우도 있다. 이 경우 ground truth 자체가 틀리므로, 경계 오차가 모두 모델의 문제라고 보기는 어렵다.

## 5.4 Depth Pro 2와의 비교

경계 오차 중 모델이 줄일 수 있는 부분과 ground truth 문제로 생긴 부분을 구분하기 위해, 같은 test 영상에 Depth Pro 2 [7]를 적용해 비교했다. Depth Pro 2는 여러 데이터셋의 깊이 정답으로 학습한 지도학습 모델로, 영상을 원본 해상도로 처리하고 transposed convolution으로 해상도를 높여 경계를 선명하게 예측하도록 설계되었다. KITTI로 학습하지 않았고 학습 방식과 모델 크기도 Lite-Mono와 크게 달라 성능을 직접 비교할 대상은 아니며, 본 프로젝트에서는 경계 오차를 해석하는 기준으로만 사용했다. 공개된 가중치로 S(24.3M)와 H+(872M) 두 모델을 추론하고, Lite-Mono와 같은 평가 코드로 평가했다.

**Ground truth 문제로 생긴 오차.** 경계에서 물체를 놓친 경우는 세 모델 모두 20% 안팎으로 비슷하다. 또 유리창이나 철망처럼 LiDAR가 물체를 통과해 뒤쪽을 측정한 점(투과 점)의 AbsRel도 세 모델 모두 약 0.355로 같다. 모델 크기와 관계없이 같은 오차가 남으므로, 이 부분은 ground truth의 문제로 보고 개선 대상에서 제외한다.

# 6. 개선 방향

## 6.1 자율주행 관점의 목표

자율주행에서 깊이 추정이 가장 직접 쓰이는 곳은 가까운 차량, 보행자, 자전거까지의 거리 판단이다. 같은 크기의 오차라도 물체를 실제보다 멀게 예측하거나 물체를 놓치면 제동 판단이 늦어지므로 더 위험하다. 반면 물체가 배경 쪽으로 번지는 오차는 물체를 크게 보는 방향이라 충돌 측면에서는 보수적이지만, 물체 옆의 빈 공간을 막힌 것으로 만들어 주행 가능 영역 추정을 해친다. 또 유리창이나 철망처럼 LiDAR 정답이 모호한 영역은 5.4절에서 세 모델의 오차가 같았으므로 개선 대상에서 제외한다.

Lite-Mono의 장점은 가벼운 구조이므로, 개선안이 연산량을 크게 늘리면 비교의 의미가 없어진다. 이에 따라 목표를 **추론 시간을 baseline Lite-Mono와 비슷하게(증가 10% 이내) 유지하면서 가까운 물체 경계의 번짐과 물체 깊이 오차를 줄이는 것**으로 정했다. 처음에는 추가 연산량 3% 이내를 기준으로 했으나, 연산량과 실제 추론 시간이 비례하지 않아 추론 시간 기준으로 바꾸었다(6.4절). 입력 해상도를 1024×320으로 키우는 방법은 경계에 효과가 있지만 연산량이 약 2.7배가 되므로 후보에서 제외했다.

## 6.2 가설

**가설 1: decoder 구조.** 5.3절과 같이 decoder가 사용하는 가장 세밀한 feature는 1/4 해상도이고, 마지막 2배 확대는 bilinear upsampling이다. 1/4 해상도 한 칸은 원본에서 약 8픽셀이므로, 4px 이상 밀린 경계가 많은 결과와 크기가 맞다. HR-Depth [9]도 Monodepth2를 분석해, 저해상도 예측을 bilinear upsampling으로 키울 때 깊이 변화가 큰 경계에서 오차가 커진다고 보고했다. 이 가설이 맞다면 1/2 해상도 feature와 학습 가능한 upsampling으로 경계 위치가 더 정확해진다.

**가설 2: 자기지도 손실.** 물체 바로 뒤의 배경 픽셀은 인접 프레임에서 물체에 가려 보이지 않는 경우가 많다. 이때 photometric loss는 그 픽셀에 물체의 깊이를 주었을 때 오히려 작아질 수 있어, 배경이 물체의 깊이로 학습된다. Chen 등 [11]은 자기지도 깊이 추정의 edge-fattening이 이 가려짐 때문에 생긴다고 분석했다. 또 edge-aware smoothness loss는 영상의 밝기 경계가 약한 곳에서 깊이 경계까지 평평하게 만든다. Lite-Mono의 smoothness 가중치는 exp(−|∂I|)이고 밝기 차이 |∂I|는 0–1 범위이므로, 가장 강한 밝기 경계에서도 가중치가 exp(−1) ≈ 0.37 아래로 내려가지 않아 경계에서 smoothness가 크게 약해지지 않는다. 이 가설이 맞다면 구조를 바꾸어도 번짐은 크게 줄지 않고, 손실을 바꾸어야 줄어든다.

**두 가설의 근거 점검.** 5.2절에서 배경 쪽 번짐은 물체 쪽 밀림의 약 4배였다. Bilinear upsampling은 양쪽 값을 대칭으로 섞으므로, 구조만이 원인이라면 경계가 양쪽으로 비슷하게 흐려져야 한다. 번짐이 한쪽으로 치우친 결과는 가설 2를 더 지지한다. 반면 경계 위치가 4px 이내로 정확한 경우가 25.4%뿐인 결과는 해상도 한계와도 맞으므로 가설 1도 배제할 수 없다. 또 Depth Pro 2와의 비교는 구조와 지도학습이 함께 다르므로 두 가설을 구분하지 못한다. 이에 따라 한 가설만 가정하지 않고, 각 가설에 해당하는 부분만 바꾸는 후보를 같은 조건에서 비교하도록 실험을 설계했다.

D는 가설 2 중 가려짐 부분에 대해 이미 효과가 보고된 방법이므로, 본 프로젝트의 후보와 비교하는 기준으로 둔다. 큰 모델의 예측을 pseudo-label로 쓰는 방법은 BoRe-Depth [13]가 이미 시도했고, Depth Pro 2 가중치는 연구용으로만 공개되어 학습에는 사용하지 않는다. 정리하면 후보로 쓴 개별 모듈은 새로운 것이 아니며, 모두 위 연구의 아이디어를 Lite-Mono에 맞게 가져오거나(A, A-lite, B, C, E) 그대로 적용한 것(D)이다. 본 프로젝트에서 직접 설계한 부분은 네 가지다. 첫째, Lite-Mono의 경계 오차를 LiDAR 경계 위치 기준으로 측정하는 평가 방법이다. 둘째, 구조 원인과 손실 원인을 같은 학습 조건에서 하나씩 바꾸어 나누는 실험 설계다. 기존 연구는 어느 한 원인만 가정하거나 여러 변경을 함께 적용했다. 셋째, 자율주행 관점에서 가까운 물체 단위로 오차를 보는 평가다. 넷째, 학습에 쓰는 photometric loss를 LiDAR 경계 주변 픽셀마다 계산해 손실이 어떤 깊이를 선호하는지 측정하는 진단이다(6.6절).

## 6.4 평가 방법

논문과 비교하기 위한 주 지표는 기존 Eigen test 지표로 유지하고, 경계 위치 지표와 물체 단위 지표를 보조로 더한다. 물체 단위 지표는 KITTI raw의 tracklet, 즉 사람이 직접 단 차량·보행자·자전거의 3D 박스 안에 들어가는 LiDAR 점만 골라 계산한다. 분할 모델을 쓰지 않으므로 분할 오류가 결과에 섞이지 않는다. 거리 구간을 0–10m, 10–20m, 20–30m로 나누어 AbsRel과 물체를 실제보다 멀게 예측한 비율을 함께 본다. Tracklet은 KITTI raw의 일부 주행에만 공개되어 있으므로, 물체 단위 지표는 Eigen test 중 해당 주행의 영상에서만 계산하며 라벨이 있는 물체에 한정된다.

후보는 물체 단위 지표가 좋아지고, 전체 AbsRel이 나빠지지 않으며, 추론 시간이 baseline Lite-Mono와 비슷할 때 채택한다. 처음에는 연산량 증가 3% 이내를 기준으로 했으나, 연산량과 실제 추론 시간은 비례하지 않는다. Lite-Mono 논문의 측정에서도 Lite-Mono는 연산량이 Monodepth2의 약 2/3이지만 두 기기 모두에서 더 느렸다. 자율주행에서는 실제 처리 시간이 중요하므로 기준을 추론 시간으로 바꾸었다.

Lite-Mono 논문은 데스크톱 GPU인 TITAN Xp와 임베디드 보드인 Jetson Xavier에서 속도를 쟀다(아래 표). 논문 본문의 표는 16장씩 묶어 처리한 이미지당 시간이고, 1장씩 처리한 값은 공식 저장소에 공개되어 있다. 자율주행에서는 카메라 영상을 1장씩 처리하므로 1장씩 처리한 시간이 실제 사용에 가깝다. 본 프로젝트에는 Jetson이 없으므로 같은 PyTorch 코드로 GPU(RTX 5070)에서 1장씩과 16장씩, CPU(4 thread)에서 1장씩 측정하고, CPU를 연산 능력이 낮은 기기의 대용으로 쓴다. 측정 기기가 논문과 다르므로 절대 시간이 아니라 baseline 대비 증가율로 비교한다. 후보는 세 조건 모두에서 추론 시간 증가가 10% 이내일 때 baseline과 비슷하다고 본다. 이 허용 폭 10%는 본 프로젝트에서 정한 값이다.

| 측정 | 1장씩 | 16장씩 | CPU 1장씩 |
|---|---|---|---|

| 재현 모델, RTX 5070 / Ryzen 7 7800X3D | 3.59 | 2.02 | 51.5 |

같은 기준으로 보면 6.5절의 후보 중 A는 16장씩 처리에서 +14%로 기준을 넘고, A-lite(최대 +2%)와 E(최대 +8%)는 기준 안에 든다. Depth Pro 2-S와 같은 채널 수(64)로 만든 E는 연산량 +82%, 추론 시간 +17%(GPU 1장씩)에서 +45%(CPU)로 기준을 크게 넘는다.

## 6.5 예비 실험

각 후보를 5 epoch 동안 짧게 학습해 방향을 확인했다. Learning rate는 학습 epoch 수와 관계없이 31 epoch 주기의 같은 cosine schedule을 사용하므로, baseline의 5번째 epoch checkpoint와 같은 조건에서 비교할 수 있다. B, A-lite, C, A 순서로 한 번에 하나씩 학습했고, E는 6.8절의 검토 후 같은 조건으로 추가로 학습했다. C의 계수 10은 실험 전에 정한 값이며, test 결과를 보고 조정하지 않았다. Seed를 고정하지 않았으므로 같은 설정으로 baseline을 한 번 더 학습해 학습 간 차이를 측정했고, 각 실험의 4번째 epoch checkpoint도 함께 평가해 checkpoint 사이의 흔들림을 확인했다. 거리 구간 지표는 LiDAR 깊이 기준이다.

전체 지표에서 B, A-lite, A의 AbsRel은 baseline보다 0.002–0.004 낮았지만, 이 차이는 baseline 자체의 인접 epoch 사이 차이(4, 5, 6번째 epoch에서 0.122, 0.118, 0.116)와, 같은 설정으로 다시 학습한 baseline의 결과(5번째 epoch 0.117) 범위 안이다. C는 AbsRel이 0.009 나빠졌고, 특히 10–20m 구간에서 0.101에서 0.120으로 나빠졌다. 0–10m AbsRel은 B, A-lite, A에서 0.089–0.091로 baseline의 0.097보다 낮았으나, baseline도 6번째 epoch에서 0.088이 되고 다시 학습한 baseline은 5번째 epoch에서 0.089였으므로 후보의 효과로 보기 어렵다.

경계 지표에서는 경계 위치가 4px 이내로 정확한 비율이 4번째와 5번째 epoch 모두 모든 실험에서 18–22%로 같았다. 후보는 경계를 정확하게 만들지 못했다. 같은 설정의 두 baseline 학습 사이에서도 5번째 epoch의 배경 쪽 번짐은 28.7%와 25.1%로 달랐다. 두 학습의 4·5번째 epoch 값(4px 이내 19.3–21.7%, 번짐 25.1–28.7%, 물체 놓침 25.9–29.8%)을 기준 범위로 보면, 두 checkpoint 모두에서 이 범위를 벗어난 것은 A-lite의 번짐(30.4%, 32.9%)과 물체 놓침(22.6%, 21.7%), A의 물체 놓침(22.8%, 25.3%)이다. A-lite의 번짐은 baseline 30 epoch 학습에서 분석한 모든 checkpoint(25.8–30.1%)보다도 높았다. 반면 baseline의 물체 놓침도 학습이 진행되면 10번째 epoch 이후 22.4–23.4%로 줄어들므로, A-lite와 A의 물체 놓침 감소는 baseline이 학습 후반에 도달하는 수준에 일찍 도달한 것일 수 있다. A는 5번째 epoch에서 번짐과 물체 놓침 모두 baseline과의 차이가 1%p 이내였다. AbsRel은 A-lite와 A가 두 checkpoint 모두 0.116으로, 범위(0.117–0.122)보다 0.001 낮았다. 이 기준 범위는 학습 2회로 잰 것이라 실제 학습 간 차이보다 좁을 수 있다. B와 C의 경계 지표는 4번째와 5번째 epoch 사이에서 크게 바뀌어 방향을 판단할 수 없었다. 예를 들어 B에서 0–10m 물체의 경계 부분을 실제보다 25% 이상 멀게 예측한 비율은 51.1%에서 39.6%로 바뀌었다.

Decoder 전체를 Depth Pro 2의 decoder 구조로 바꾼 E(6.8절)도 같은 기준으로 보면 A, A-lite와 같은 방향이었다. 두 checkpoint 모두에서 번짐은 범위보다 많았고(30.3%, 29.5%), 물체 놓침은 범위보다 적었다(25.5%, 23.7%). 4px 이내 비율(18.3%, 19.1%)은 범위보다 약간 낮았다. AbsRel은 5번째 epoch에서 0.114로 범위보다 낮았지만 4번째 epoch에서는 0.120으로 범위 안이었고, 0–10m AbsRel(0.089)은 baseline 재학습과 같았다. 즉 decoder의 일부가 아니라 전체를 바꾸어도, 5 epoch에서는 경계가 더 정확해지거나 번짐이 줄지 않았다.

또 baseline의 30 epoch 학습 과정에서 같은 지표를 계산하면, 4px 이내 비율은 5번째 epoch의 19.3%에서 20번째 epoch의 25.9%로 오르지만, 배경 쪽 번짐은 분석한 5번째부터 30번째 epoch까지의 checkpoint 8개에서 26.1–30.1% 범위에 머문다. 한 번의 학습 결과이지만, 번짐은 학습을 더 해도 줄지 않았다.

정리하면 5 epoch 예비 실험에서 가설 1의 후보(A, A-lite)와 가설 2 중 smoothness 후보(B, C) 모두 번짐을 줄이지 못했다. 다만 이 결과는 실험마다 한 번씩 학습한 결과이므로, 작은 차이는 판단하지 않았다. 남은 원인 후보인 학습 신호를 확인하기 위해, 6.6절에서 손실 함수가 경계 주변에서 어떤 깊이를 선호하는지 직접 측정했다.

## 6.6 손실 함수 진단

학습 없이, 학습에 쓰는 photometric loss가 경계 주변 배경 픽셀에서 정답 깊이와 번진 깊이 중 어느 쪽을 더 작게 평가하는지 측정했다. Baseline의 30번째 epoch checkpoint와 그 pose network를 사용했고, 5.2절의 LiDAR 경계 중 앞뒤 프레임이 있고 차량이 움직인 2,690개를 대상으로 했다. 경계와 같은 행의 픽셀마다 물체의 깊이와 배경의 깊이를 각각 주고, 학습과 같은 방식(640×192 입력, 0.85×SSIM + 0.15×L1, 인접 프레임 중 최솟값)으로 손실을 계산했다. 깊이는 같은 영상의 median scaling 비율로 모델의 scale로 바꾸었고, 차량이 정지해 두 깊이의 warp 위치 차이가 0.5px 미만인 픽셀은 제외했다.

| 위치 | 인접 프레임 ±1 (학습과 같음) | ±1, ±2 |
|---|---|---|
| 물체 내부 1–6px | 68% | 66% |

물체 내부에서도 68%에 그쳐 photometric loss는 픽셀 하나 단위로는 오차가 큰 기준이다. 그러나 경계에서 먼 배경(26%)과 비교하면, 경계에서 약 4px(원본 약 8px) 이내의 배경에서는 물체 깊이를 고르는 비율이 뚜렷이 높고, 경계 바로 옆에서는 50%로 두 깊이를 구분하지 못한다. 인접 프레임을 ±2까지 늘려도 결과가 거의 같아, 학습에 쓰는 프레임을 늘리는 방법으로는 해결되지 않을 것으로 예측했다.

경계마다 배경 1–4px에서 손실이 물체 깊이를 선호하는지 판정했다(2,690개 중 33%가 해당). 그런 경계에서 학습된 모델이 4px 이상 번지는 비율은 35%로, 나머지 경계의 24%보다 11%p 높았다. 이 차이는 밝기 대비 하위·중간·상위 1/3 경계 모두에서 나타났다(32% 대 24%, 34% 대 24%, 40% 대 25%). Edge-aware smoothness가 약해지는 고대비 경계에서도 같은 관계가 유지되므로, 이 관계는 smoothness만으로는 설명되지 않는다.

이 결과는 가설 2와 맞는다. 다만 이 분석은 상관관계를 본 것이다. 손실의 치우침과 번짐이 같은 경계에서 함께 나타난다는 것을 보여 줄 뿐, 손실이 번짐의 원인임을 증명하지는 않는다. 예를 들어 얇은 물체처럼 두 가지 모두에 불리한 경계가 함께 작용했을 수 있다. A와 A-lite가 번짐을 줄이지 못한 결과, 학습을 더 해도 번짐이 줄지 않은 결과와는 일관된다. 다만 이 측정으로는 원인이 가려짐인지 경계 픽셀의 색 혼합인지 구분하지 못한다. 또 pose는 학습된 pose network의 추정값이고, 경계 바로 옆 픽셀은 3×3 SSIM 영역이 경계에 걸치는 영향도 받는다.

| 가설 1: decoder 해상도와 bilinear upsampling | 후보 A, A-lite, E (6.5절) | 4px 이내 비율이 baseline 범위를 넘지 못함. A-lite는 물체 놓침을 줄이고 번짐을 늘림, A는 물체 놓침만 줄임. Decoder 전체를 Depth Pro 2 구조로 바꾼 E도 물체 놓침은 줄고 번짐은 늘어 A-lite와 같은 방향. 모두 5 epoch, 한 번씩 학습한 결과 | 5 epoch 예비 실험에서는 지지되지 않음 |
| 가설 2: smoothness가 경계를 덮는다 | 후보 B, C (6.5절), 밝기 대비별 진단 (6.6절) | 번짐이 일관되게 줄지 않고 C는 AbsRel이 나빠짐. smoothness가 약한 고대비 경계에서도 번짐과 손실 선호의 연결이 유지됨 | 지지되지 않음 |
| 가설 2: photometric loss가 번진 깊이를 선호한다 | 학습 길이별 분석 (6.5절), 손실 진단 (6.6절) | 경계 바로 옆에서 손실이 두 깊이를 구분하지 못하고(50%) 약 8px까지 물체 깊이 쪽으로 치우침. 그런 경계에서 번짐 35%(나머지 24%). 번짐은 30 epoch까지 26–30% 유지 | 지지 (상관관계) |
| 가려짐이 원인이면 인접 프레임을 늘려 해결된다 | ±2 프레임 손실 진단 (6.6절) | 손실의 선호가 거의 변하지 않음 | 지지되지 않음 |
<!-- /full -->

종합하면, Lite-Mono는 논문의 정확도를 재현했지만 물체와 배경의 경계에서 물체의 깊이가 배경 쪽으로 번지는 한계가 있다. 이 번짐은 Depth Pro 2가 절반으로 줄인 오차이므로 개선할 여지가 있다. 그러나 한 번의 30 epoch 학습에서 번짐은 학습을 더 해도 줄지 않았다. 원인으로 세운 두 가설 중 decoder 구조와 smoothness를 바꾼 후보는 5 epoch 예비 실험에서 번짐을 줄이지 못했다. 구조 쪽은 처음 후보가 decoder의 마지막 단계만 바꾼 작은 변경이었으므로, decoder 전체를 Depth Pro 2의 구조로 바꾼 E도 시험했다. E도 번짐을 줄이지 못했고, A·A-lite처럼 물체 놓침은 줄이고 번짐은 늘리는 방향이었다. 다만 모두 5 epoch, 한 번씩 학습한 결과이며, encoder나 입력 해상도를 바꾸는 변경은 시험하지 않았다. 반면 손실 진단에서는 photometric loss가 경계 바로 옆에서 정답과 번진 깊이를 구분하지 못했고, 손실이 물체 깊이 쪽으로 치우친 경계에서 번짐이 더 많았다. 이에 따라 다음 단계에서는 경계에서의 학습 신호를 바꾸는 방법을 우선 시험한다.

실험 과정에서 처음의 해석을 고친 경우도 있었다. 5 epoch 결과를 처음 비교했을 때는 B, A-lite, A가 0–10m에서 baseline보다 좋아 보였다. 그러나 baseline 자체도 한 epoch 사이에 그만큼 바뀌었고, 같은 설정으로 다시 학습한 baseline도 같은 값을 냈다. 그래서 이를 후보의 효과로 보지 않았다. 이 경험에 따라 이후 비교는 여러 checkpoint와 두 번 이상의 학습을 기준으로 한다(6.8절).

## 6.8 향후 계획

손실 진단 결과에 따라, 첫 번째 다음 후보는 경계에 photometric loss가 아닌 신호를 주는 방법이다. 우선 분할 결과로 경계 양쪽을 분리하는 후보 D(Chen 등 [11])를 구현해 비교한다. 이때 6.6절의 진단에서 손실이 모호했던 경계 주변 약 4px에만 추가 신호를 주는 형태를 함께 시험한다. 큰 깊이 모델의 경계를 pseudo-label로 쓰는 방법(BoRe-Depth [13])도 같은 목적이지만, 학습에 사용할 수 있는 모델로 한정한다. A-lite는 물체를 놓치는 경계를 줄였으므로 손실 쪽 후보와 함께 적용하는 조합도 비교한다.

구조 쪽도 더 큰 변경으로 다시 확인한다. Depth Pro 2의 공개 코드를 보면, encoder의 가장 세밀한 정보는 16픽셀 패치 단위로, KITTI 원본 폭 기준 약 78칸이다. 이는 Lite-Mono의 1/4 해상도 feature(160칸)보다 거칠다. 그런데도 Depth Pro 2의 경계가 선명하므로, 후보 A처럼 고해상도 정보를 더하는 것보다 decoder가 해상도를 높이는 방식이 중요할 수 있다. Depth Pro 2의 decoder(DPT [14])는 모든 단계에서 residual block으로 feature를 정제한 뒤 transposed convolution으로 해상도를 2배씩 높인다. 반면 Lite-Mono의 decoder는 모든 단계에서 bilinear upsampling을 쓴다. 이 decoder 구조를 Lite-Mono encoder에 붙인 후보 E를 구현했다. Depth Pro 2-S와 같은 채널 수(64)에서는 연산량이 82% 늘어나므로, 채널 수를 24로 줄여 연산량 +2.0%, 파라미터 −3.4%, 추론 시간 +3–8%로 맞춘 형태를 5 epoch 학습했다. E는 번짐을 줄이지 못했다(6.5절). Depth Pro 2의 decoder 구조를 가져와도 자기지도 학습에서는 경계가 선명해지지 않았으므로, 학습 신호가 핵심이라는 해석과 맞는다. 다만 Depth Pro 2는 encoder와 학습 데이터도 다르고 깊이 정답으로 학습한 모델이므로, 구조의 효과를 완전히 배제하지는 못한다. E는 A-lite처럼 물체 놓침을 줄였으므로, 손실 쪽 후보와 함께 적용하는 조합 후보로 둔다.

실험 방법도 보완한다. 5 epoch 단일 checkpoint 비교는 epoch 사이의 흔들림이 후보 간 차이보다 커서, 이후에는 여러 checkpoint의 평균과 두 번 이상의 학습으로 비교한다. 또 후보 평가에 6.6절의 진단을 함께 사용해, 손실이 모호한 경계에서 번짐이 줄었는지 확인한다. 효과가 있는 후보는 30 epoch 전체 학습으로 baseline과 비교하고 그 결과는 최종 보고서에 정리한다. 이번 범위에서 제외한 트인 도로의 먼 나무와 수풀 오차, 움직이는 물체 문제는 최종 보고서에서 한계로 다룬다.
